# SyncCampus Admin Dashboard

Design the **Admin Dashboard** as the central management interface for SyncCampus.

The admin has access to the entire campus system, including students, teachers, departments, classrooms, timetables, examinations, announcements, and system settings.

Despite having many controls, the interface should remain **simple, organized, and easy to navigate**.

The admin should be able to understand the current campus situation at a glance and perform important actions in a few clicks.

---

# 1. Overall Design

Use the same visual identity as the Student and Teacher dashboards.

### Style

- Clean white interface
- Very light blue/grey background
- Blue as the primary color
- Rounded cards
- Subtle shadows
- Clean icons
- Modern typography
- Plenty of whitespace
- Minimal animations
- No unnecessary graphics

The dashboard should feel like a **modern Google-style management panel**, not an old college ERP.

# 15. Conflict Detection

This is an important feature for the admin.

Before saving a timetable change, SyncCampus should automatically check for conflicts.

For example:

### ⚠️ Timetable Conflict

Room 204 is already assigned to:

**Web Development**

10:00 AM – 11:00 AM

You are trying to assign:

**DBMS**

10:00 AM – 11:00 AM

Options:

**Choose Another Room**

**Change Time**

This prevents timetable mistakes.

The same system should check:

- Teacher double-booking
- Classroom double-booking
- Division double-booking
- Exam room conflicts

# 18. Important Confirmation System

Because admin changes can affect hundreds or thousands of students, important actions should require confirmation.

Example:

### Reschedule Lecture?

**DBMS**

BSc IT • Semester 3 • Division A

Current:

10:00 AM • Room 204

New:

2:00 PM • Room 305

**142 students will be affected.**

[Cancel] [Confirm Change]

This makes the system safer and prevents accidental changes.

---

# 19. Automatic Synchronization

This is the core of SyncCampus.

Example:

Admin changes:

**DBMS**

10:00 AM → 2:00 PM

↓

Central SyncCampus system updates

↓

Teacher dashboard updates

↓

Student dashboards update

↓

Affected students receive notification

**🔔 Timetable Updated**

DBMS has been rescheduled to **2:00 PM**.

The admin should never need to separately inform teachers or students.

# 21. Important Design Principle

Do **not** put every admin function on the home screen.

The home screen should answer:

> **"What is happening on my campus right now?"**

The sidebar provides access to detailed management.

This keeps the admin dashboard powerful without making it confusing.

---

# SyncCampus Role Structure

The three interfaces should feel like one product:

### Student

**View**

"What do I have today?"

### Teacher

**View + Manage**

"What do I have, and what do I need to change?"

### Admin

**Control**

"What is happening across the entire campus, and what needs to be managed?"

All three use the same design system, while their permissions and available actions are different.
